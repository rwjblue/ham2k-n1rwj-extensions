limits and overlay operating-time accounting remain outside this implementation.
Validation is source, unit and bundle coverage; installed-app and on-air
acceptance remain unverified. See the

## n1rwj-zombie

- Add the optional **Zombie Shuffle** panel: a purple graveyard, warm radio
  shack and headphone-wearing Zombie. Qualifying new contacts get a short
  shuffle; rebirths get **BACK FROM THE DEAD!**, and copied `4321` bonus
  exchanges get sparkles and a party hat. **CQ BOO!** is a visual greeting.
- Show your spooky identity, QSO/bonus counts, total score and four score
  groups. The 666-point Crummy Band lantern lights after the first qualifying
  contact. Scoring and submission calculations are unchanged.
- Follow the **Rebirth watch**, with independent two-hour timers per callsign
  and actual band. Detailed watch times are UTC; visible countdowns refresh
  once a minute from cached state. 10m and 15m share scoring but keep separate
  timers. **Eligible again does not mean currently on air.**
- Browse the **Book of the Undead** for copied spooky names, locations,
  leading-zero numbers and band visits. Native Info gains a playful score
  breakdown and clearly separated current exchange/history hints. Explicit
  clearing remains authoritative; cached hints make no live readiness claims.
- Keep celebrations quiet when opening/reopening a panel, editing contacts or
  restoring previously seen records. Motion respects the system preference
  and panel setting. Narrow scenes prioritize callsign, band and countdown;
  older hosts show the detailed watch automatically.

Add **Edit Layout → Add a Panel → Zombie Shuffle** to a dedicated operation.
Panel settings choose the scene, detailed watch or book. Requires extension
API 1 and the declared shared libraries. Logs with start/break setup overrides
show guidance instead of a guessed timeline; native scoring, Info and exports
retain their segment-aware behavior. Spot lanterns and tuning are a later
increment; the panel makes no radio or network calls.

Unit, bundle, browser-preview and installed-kernel checks passed. Installed-app
UI, native scheduling and on-air acceptance remain unverified. See the
[operator guide](https://github.com/rwjblue/ham2k-n1rwj-extensions/blob/v0.14.0/extensions/contests/n1rwj-zombie/README.md).

## Repository notes

- All 11 bundles and their SHA-256 files use the synchronized version. Only
  Zombie Shuffle and CQ WW are selected for catalog submission. Dependencies
  and shared runtime code are unchanged; a version bump alone does not select
  the other nine extensions.
- Verification includes lint, strict runtime/test/task typechecks, **1,813 tests
  across 130 files** and all 11 official ES2020 builds and packages. Zombie's nine hooks
  activate in the installed Ham2K Mac Logger (Next) 26.9.0 build 180 kernel.
- `mise run zombie:preview` generates 18 synthetic scenes/views plus JSON and
  a static SVG. Browser rendering and pose playback are approximations of the
  native renderer and never access a logger, radio or user's contacts.
- CQ WW runtime source and translations match the official PR source branch.
  Zombie is independent of the temporary contest branches and needs no upstream
  behavior synchronization. See the
  [verification record](https://github.com/rwjblue/ham2k-n1rwj-extensions/blob/v0.14.0/docs/VERIFICATION.md).
