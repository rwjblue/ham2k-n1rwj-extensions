# v0.17.0 — Native history downloads and newer panel controls

CWT, MST and SST use Ham2K’s built-in N1MM downloader. Native data-file
persistence replaces oversized cache records, and newer hosts gain folded
settings sections and a scrollable BKG panel with live dial context.

## Shared changes

- Updated the published extension SDK and official build/packaging tools to
  1.13.0 for every extension. Existing shared-library compatibility ranges
  remain unchanged. Each extension declares the minimum API its features need.
- Updated vulnerable build-only transitive dependencies: the official toolchain
  uses a scoped Sharp 0.35.5 override, and the Vite lock resolves to 8.3.5.

## n1rwj-bigfoot

No extension-specific changes for BIGFOOT Hunt.

## n1rwj-bkg

- Requires Ham2K extension API 13 and requests **read-only radio access**.
- All member-card sections remain reachable by native scrolling in short
  panes. Pinch or drag the right edge to adjust temporary spot-list spacing.
- A fixed strip follows the logging radio’s frequency, mode and connection
  through native scene bindings. Radio events update 2m CW guidance without
  polling or scanning the full log. Dial status does not prove a contact.
- High-contrast and enlarged-text layouts retain accessible Markdown; roster
  lookup and hunting remain usable without a connected radio.

## n1rwj-contest-calendar

No extension-specific changes for N1RWJ Contest Calendar.

## n1rwj-cwt

- Requires extension API 11. Ham2K discovers and downloads the latest CWOPS
  call-history file through its built-in N1MM adapter, including pagination,
  form handling and freshness checks.
- Native Data Files keep the existing refresh, removal and offline cache
  controls. Removed the redundant full-file KV cache to fit new host budgets.
- Existing name/number suggestions, explicit corrections and clearing,
  logged-contact fallback and export conventions remain compatible.

## n1rwj-mst

- Requires extension API 11 and uses Ham2K’s native `ICWC-MST` history adapter.
  Refresh and offline replay remain in native Data Files.
- Removed custom download-page parsing. History still suggests names only;
  received serials must be copied from each contact.

## n1rwj-psk-reporter

No extension-specific changes for N1RWJ PSK Reporter.

## n1rwj-randomgram

No extension-specific changes for N1RWJ RandomGram.

## n1rwj-rbn

- Requires extension API 12. Native settings sections remember their folded
  state. My Signal guidance and export choices start folded; spot filters
  stay open, with health diagnostics outside folded sections.
- Existing saved setting keys and placement under Spotting are preserved.

## n1rwj-skcc

- Requires extension API 12. Native settings sections remember their folded
  state, while retaining existing setting keys and placement under Activities.
- Native Data Files persist and replay the roster offline. Removed the
  redundant full-roster KV cache so current host storage budgets cannot break
  roster refreshes. Invalid or unexpectedly shortened rosters retain the
  previous valid runtime index.

## n1rwj-sst

- Requires extension API 11 and uses Ham2K’s native `K1USNSST` history adapter.
  Refresh and offline replay remain in native Data Files.
- Removed custom download-page parsing. Names and valid state/province/DX
  suggestions retain their contest-specific meaning and editable precedence.

## n1rwj-wrt

No extension-specific changes for N1RWJ Weekly RTTY Test.

## n1rwj-zombie

No extension-specific changes for N1RWJ Zombie Shuffle.

## Repository notes

- All twelve extensions share this version and receive the common SDK/tools
  update. Older hosts retain compatible earlier catalog versions; the newly
  adopted features require the API levels stated above.
- CWT behavior, tests and documentation are synchronized to the source branch
  of [Ham2K/extensions PR #1](https://github.com/ham2k/extensions/pull/1).
  Other extensions and personal release packaging are exempt from that sync.
- Full lint, strict types, tests, ES2020 bundles and official packaging checks
  passed. Installed Next build 184 kernel verification runs under Node VM;
  native API 13 gestures, device UI and on-air acceptance are separate checks.
