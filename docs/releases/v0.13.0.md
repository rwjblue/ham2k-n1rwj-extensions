# v0.13.0 — BIGFOOT spots in the forest

Find fresh BIGFOOT stations and request radio tuning from the existing hunt panel.

## Shared changes

- Updated the shared extension SDK from 0.12.0 to 0.12.13 and official build/packaging tools from 0.8.0 to 0.13.0. All bundles use the updated runtime helpers, including incomplete-call scoring guards, country-file normalization, and export metadata cleanup. Existing shared-library compatibility ranges are preserved.

## n1rwj-bigfoot

- Fresh cached spots now appear inside the existing forest: teal letter beacons, W4S on the Skunk Ape card, and a station lead in Bigfoot's journal. Earned gold letters and Mixed-only dots retain their meaning. W7O marks only the next missing O.
- Select a spotted letter or the journal's Tune button to request frequency and supported-mode tuning of the connected logging radio. **Enter the callsign in the logger manually.** No report arrival changes the radio; unavailable radios leave manual tuning possible.
- The newest report per callsign follows the selected hunt mode, native Spots filters, and a 15-minute window by default. Optional all-cache and 5/30-minute settings, narrow-panel browsing, expiry checks, and exact event-credit rules keep the leads useful. The detailed checklist includes a station list.
- **Requires extension API 7 and radio-write permission.** Update Ham2K if the new version is unavailable on an older host. There is no separate spots pane to add.

## Repository notes

All eleven extensions retain one synchronized version. The root dependency updates select all eleven for catalog submission. BIGFOOT feature code is independent of the temporary contest branches; the shared SDK behavior is synchronized to their verified source branches. Deterministic unit, bundled-sandbox, packaging, and native component checks are separate from an installed-app or on-air radio acceptance test.
