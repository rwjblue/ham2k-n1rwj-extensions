# v0.6.1 — CQ WW RTTY spot multipliers

CQ WW RTTY now highlights potential new multipliers in the spots list and
live logging entry, even before a received exchange has been entered.

## n1rwj-cqww

- Identify potential new country and CQ zone multipliers from bare RTTY spots,
  regardless of the spot source. RBN requires no contest-specific changes.
- Reuse a valid exchange already copied from the same call on another band to
  identify zone and state/province opportunities. Available lookup-state hints
  can also identify a QTH multiplier; unknown states remain unknown.
- Preserve explicit exchange corrections and clearing. Potential multipliers
  never award points or consume multiplier or duplicate history; incomplete
  logged exchanges still score zero until completed.
- Keep band/mode restrictions, single-band entry rules, and duplicate notices
  consistent between spots, live logging, and saved QSOs.
- This remains a temporary preview of
  [Ham2K/extensions PR #2](https://github.com/ham2k/extensions/pull/2).
  Disable official CQ WW while using this preview. Once the official extension
  includes these changes, disable the preview and enable the official version.

## Repository notes

- All seven extensions and shared packages advance together to 0.6.1. Only
  CQ WW has behavior changes and is selected for catalog submission; GitHub
  archives all seven bundles and their checksum files.
- CQ WW source, regression tests, and documentation are synchronized with the
  upstream PR source branch. Personal versioning stays in this repository;
  CWT behavior and its upstream branch are unaffected.
- Validation covers bare spot candidates, independent candidate previews,
  checkpoint replay, operator corrections, and the packaged scoring hook.
  Installed Ham2K build 175 JavaScript-kernel checks run under Node VM;
  native UI and on-air verification remain pending.
- External dependency versions and manifest compatibility ranges are unchanged.
