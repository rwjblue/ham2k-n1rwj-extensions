# v0.12.0 — A forest for the BIGFOOT hunt

Follow your BIGFOOT hunt through an illustrated Pacific Northwest forest.
Bigfoot celebrates new letters, the Skunk Ape gets its own moment, and the
built-in Info pane makes CW and Mixed progress easier to read.

Synthetic preview rendered with the native scene component:

![BIGFOOT forest scene with a new-letter celebration](https://github.com/rwjblue/ham2k-n1rwj-extensions/releases/download/v0.12.0/bigfoot-scene-demo.gif)

## n1rwj-bigfoot

- Turn the optional Hunt panel into a forest with a friendly Bigfoot, glowing
  fireflies, seven letter tiles, and a separate Skunk Ape bonus card. Newly
  earned letters sparkle while Bigfoot hops and waves for four seconds;
  finishing BIGFOOT brings out the stars. **Wave hello** gives him a greeting
  whenever you want one, without changing your log or earning credit.
- Keep CW in focus, with Mixed progress alongside it. Gold tiles show earned
  letters; gold dots identify Mixed credit still needed in the selected mode.
  **O₁** and **O₂** stay separate: the second W7O needs a different band,
  actual mode, or UTC date. An all-CW pair needs another band or UTC date.
  W4S remains a separate bonus, and Mixed completion preserves the CW hunt.
- Add emoji to built-in **Info**: event and letter notes while entering a
  callsign, plus CW/Mixed totals, worked/needed states for each letter and
  both O contacts, a separate bonus row, and earned completion banners in the
  scored hunt summary. These Info improvements need no extra panel.
- Respect system reduced motion and the panel's **Animate the forest and
  celebrations** setting. Opening an existing hunt, changing modes, editing
  a contact, or logging a repeat does not replay an award. Choose **Detailed
  checklist** for contact dates, bands, modes, and both O contacts' evidence;
  older hosts show that checklist automatically.

In a **BIGFOOT Hunt 2026** operation, choose **Edit Layout → Add a Panel →
BIGFOOT Hunt** once, then leave the panel visible while you log. Existing Hunt
panel placements upgrade in place. Use its tune settings to choose **Hunt
mode**, **Forest scene / Detailed checklist**, and motion. Very short panels
hide the greeting button to keep progress readable.

The confirmed 2026 event rules and exports retain their existing behavior.
The forest shows progress from this operation only. Automated, native scene
component, and installed build-180 JavaScript kernel checks passed; using the
updated extension inside the installed logger and on air remains unverified.
See the [operator guide](https://github.com/rwjblue/ham2k-n1rwj-extensions/blob/v0.12.0/extensions/activities/n1rwj-bigfoot/README.md).

## Repository notes

- All 11 extension bundles and their SHA-256 files use synchronized version
  0.12.0. Only BIGFOOT Hunt is selected for catalog submission. Dependencies,
  shared runtime code, and the private spot-filter protocol are unchanged;
  the version bump alone does not select other catalog entries.
- Validation covers lint, strict runtime/test/task typechecks, **1,604 tests
  across 118 files**, and all 11 official ES2020 builds and packages. **46
  native scene component checks** use synthetic hunt states, including narrow
  layouts, celebrations, and reduced motion. The installed **Ham2K Mac Logger
  (Next) 26.9.0 build 180** JavaScript kernel accepts the extension. Component
  and kernel checks are separate from installed-logger UI and on-air acceptance.
- Run `mise run bigfoot:preview` for an interactive browser preview of
  synthetic hunts, both O contacts, completion, greeting, and reduced motion.
  It writes `dist/bigfoot-scene-preview.html` and companion scene JSON without
  accessing your logger or radio; browser pose playback approximates the
  native scene.
- BIGFOOT presentation and personal packaging changes do not affect CWT or
  CQ WW behavior, so no upstream synchronization is required. See the
  [verification record](https://github.com/rwjblue/ham2k-n1rwj-extensions/blob/v0.12.0/docs/VERIFICATION.md).
