# v0.7.1 — RBN spot filters and easier resets

RBN adds CW speed limits, remembers receiver-continent preferences, and makes
spot-filter defaults easier to restore. Only RBN changes behavior in this release.

## n1rwj-cqww

No extension-specific changes for N1RWJ CQ WW (temporary).

## n1rwj-cwt

No extension-specific changes for N1RWJ CWT.

## n1rwj-mst

No extension-specific changes for N1RWJ ICWC MST.

## n1rwj-psk-reporter

No extension-specific changes for N1RWJ PSK Reporter.

## n1rwj-rbn

- Added optional minimum and maximum CW speeds in WPM. Bounds are inclusive
  and may be left open; digital spots are unaffected. CW spots without a known
  positive speed are excluded while a speed limit is enabled.
- Receiver-continent selections now survive restarts, including an explicit
  choice of all continents. On first use, nearby receivers can suggest a local
  continent from device location, falling back to the last nonempty selection
  or all continents. Existing choices are preserved.
- The initial continent suggestion may request location permission. It is an
  approximate suggestion using receivers within 250 km, not a boundary lookup;
  no device coordinates are sent to a network service or saved in settings.
  Refresh Spots after the location attempt finishes to apply its result.
- Added visible defaults and individual reset controls, plus **Reset all spot
  settings**. Distance and speed resets clear their related fields together;
  continent controls distinguish restoring the default from allowing all
  continents. Resets preserve My Signal settings and reception caches.

## Repository notes

- All extensions and shared packages advance to 0.7.1. GitHub archives all
  seven bundles; only RBN is selected for catalog publication.
- RBN retains its extension API 3 requirement. No root dependencies or shared
  runtime code changed since v0.7.0.
- RBN behavior and personal release packaging are exempt from upstream
  CWT/CQ WW synchronization; neither contest's behavior changed.
- Deterministic unit and bundle tests cover the new filters and settings.
  These checks do not establish native Ham2K UI or location-permission behavior.
