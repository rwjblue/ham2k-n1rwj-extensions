# v0.8.0 — Native My Signal controls and RBN reception exports

RBN and PSK Reporter gain native My Signal controls with a report-window choice
beside Band. RBN can export collected reception evidence in six text formats.
Contest exports get clearer choices and filename defaults, and SST setup offers
named location suggestions while preserving operator corrections.

## Shared changes

- Updated the Ham2K extension SDK from 0.9.0 to 0.12.0 and extension tools from
  0.7.0 to 0.8.0. Existing host shared-library compatibility ranges are preserved.
- Refreshed development dependencies and CI tooling. Contest scoring arithmetic
  and shared-library requirements are unchanged.

## n1rwj-cqww

No extension-specific changes for N1RWJ CQ WW (temporary).

## n1rwj-cwt

- Adds dedicated CWT ADIF and Cabrillo choices with filename-template defaults.
  Preserves UTC session-specific filenames, contest tags, exchange fields and
  existing generic export requests. New contest entries have independent
  preferences; existing generic export preferences are not migrated.
- These export changes are synchronized with the official CWT implementation in
  [Ham2K/extensions PR #1](https://github.com/ham2k/extensions/pull/1).

## n1rwj-mst

- Adds dedicated MST ADIF and Cabrillo choices with filename-template defaults.
  Preserves compact filenames, contest tags, per-contact serial exchanges and
  existing generic export requests. New contest entries have independent
  preferences; existing generic export preferences are not migrated.

## n1rwj-psk-reporter

- My Signal now uses native Band, Window and Sort dropdowns, Status/About tabs,
  and Refresh/Details/Back buttons around the existing map and receiver reports.
- Window offers 1/3/5/10/15/30/45/60 minutes. Its selection is temporary for each
  panel placement and survives refresh and unrelated settings changes. Changing
  the saved Report window applies that default; switching operations or
  restarting returns to saved defaults. PSK Reporter retains its saved View.
- Keeps exact MQTT subscriptions, cached reports and history cooldowns.
  Refresh remains asynchronous, and obsolete operation/configuration events are
  guarded. Narrow panes wrap controls and give accurate compact-map guidance.
- **Requires a Ham2K host supporting extension API 5.** Older hosts can continue
  using the previous compatible release until updated.

## n1rwj-rbn

- My Signal now uses native Band, Window and Sort dropdowns, Map/Receivers/Both
  choices, Status/About tabs, and Refresh/Details/Back buttons. The existing
  cartography, source attribution and receiver reports are preserved.
- Window offers 1/3/5/10/15/30/45/60 minutes. View and filtering choices remain
  temporary per placement. Changing a saved default applies that choice;
  switching operations or restarting returns to saved defaults. Refresh remains
  asynchronous and keeps the existing cache and request-backoff behavior.
- Adds HTML, Markdown, observation CSV, collected-evidence JSON, SVG map and
  contact-context CSV reception exports in the operation's Exports view.
  Companion files share frozen local evidence and receiver metadata; generating
  them starts no network request. Reports show collection gaps and provenance.
- Adds bounded **Save reception evidence**, off by default in My Signal tune
  settings. Enable it for future visible-panel requests during an operation.
  Without recording, exports can use an explicitly identified rolling-cache
  snapshot. Display filters do not filter the archive. See the
  [reception export guide](https://github.com/rwjblue/ham2k-n1rwj-extensions/blob/v0.8.0/docs/RBN-EXPORTS.md)
  for limits and interpretation. PNG and ZIP exports remain unsupported.
- **Requires a Ham2K host supporting extension API 5.** Older hosts can continue
  using the previous compatible release until updated. At normal text sizes,
  320–430-pixel layout fixtures add no toolbar row and reduce map height by only
  four logical pixels. Large text can wrap controls to keep captions readable.

## n1rwj-sst

## Repository notes

- All seven extensions and shared packages advance to 0.8.0. Universal root
  dependency changes select every extension for catalog submission; GitHub
  archives all seven bundles and their SHA-256 checksums.
- Validation covers 1,174 tests across 87 files, lint, strict runtime/test/task
  typechecks, seven ES2020 builds, official packaging and release checksums.
  Installed Ham2K Next 26.9.0 build 177 kernel checks run under Node VM with
  simulated timer wakes, rather than native lifecycle scheduling.
- Temporary API-5 pilots on macOS Next build 177 verified synthetic native
  control commits, readable 320/390-pixel panes, responsive refresh and
  Details/Back state restoration. All test placements and the pilot were
  removed. Mobile devices, large OS text, full keyboard/screen-reader traversal,
  high contrast, reduced motion, production lifecycle behavior and native
  reception-export save/share remain outside that acceptance scope. See the
  [verification record](https://github.com/rwjblue/ham2k-n1rwj-extensions/blob/v0.8.0/docs/VERIFICATION.md).
- CWT changes belong to PR #1; CQ WW behavior and PR #2 are unchanged.
  Mini-contest-only, reception-only, personal versioning and repository tooling
  changes are exempt from official contest synchronization requirements.
