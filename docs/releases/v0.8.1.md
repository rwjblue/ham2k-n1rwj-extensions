# v0.8.1 — SST call-history import recovery

SST call-history refreshes now tolerate unsupported location values in
individual records, keeping the rest of the file available for suggestions.

## n1rwj-cqww

No extension-specific changes for N1RWJ CQ WW (temporary).

## n1rwj-psk-reporter

No extension-specific changes for N1RWJ PSK Reporter.

## n1rwj-rbn

No extension-specific changes for N1RWJ RBN.

## n1rwj-sst

- Unsupported location values such as `CWA` and `SM` no longer reject the entire
  SST history file. Their callsigns and names remain available, while unsupported
  location hints are omitted and counted as parser warnings.
- Valid locations and duplicate-field precedence are preserved. Numeric exchanges
  are never used as SST locations, and unsupported values are never converted to
  `DX`. Malformed files, wrong-contest files and failed downloads still retain the
  previous successful cache.

## n1rwj-wrt

No extension-specific changes for N1RWJ Weekly RTTY Test.

## Repository notes

- All seven extensions and shared packages advance to 0.8.1. Only SST is selected
  for catalog submission; GitHub archives all seven bundles and their checksums.
- Validation covers 1,180 tests across 87 files, lint, strict runtime/test/task
  typechecks, seven ES2020 builds and official packaging. The downloaded
  `K1USNSST-064.txt` loads all 15,682 calls in the bundled sandbox, including
  serialized offline replay, with five warnings: three duplicate calls and two
  unsupported locations. This is bundle verification, not a native Ham2K test.
- The SST-only behavior change is exempt from CWT and CQ WW upstream
  synchronization. Other contest behavior and dependencies are unchanged.
